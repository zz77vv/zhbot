# Telegram 综合报单机器人 V1.0（开发中）

从清理后的 `main` 全新编写，未恢复旧 PR #1。Python 3.12 + SQLite，无第三方运行依赖。

**当前处于测试验收阶段。测试机器人已完成一笔 2 USDT 的真实付款与入账核对。正式上线仍需完成管理员和客户的完整流程验收。源码默认关闭充值，测试环境需显式启用。**

已实现并通过离线测试的范围：数据库商品管理、逐项新增/修改/上下架/排序、持久草稿和字段、纯文字批次整批冻结、单笔混合资料、回单引用回复暂存/查看/删除、完成交付后扣费、管理员空单/取消退款及二次确认、积分调整与审计、逐子订单结算/批次汇总、故障隔离与人工核实恢复。

## 本地验证

```sh
python --version  # 3.12+
python -m unittest discover -s tests -v
python -m compileall -q zhbot tests
```

## 运行前准备

复制 `.env.example` 到受保护的 `.env`，填写 Token、管理员 ID，限制权限为 `600`。环境文件采用普通 `KEY=value`，示例中无真实密钥。当前必须从源码仓库根目录运行，迁移文件也需保留。

```sh
set -a
. ./.env
set +a
python -m zhbot migrate
python -m zhbot check
# 仅在自己控制的测试机器人中进行验收：
python -m zhbot run
```

没有自动加载 `.env`。不配置凭据也可以运行全部离线测试。不要把 `.env`、数据库、回单、日志、备份上传 GitHub。

客户使用 `/start` 选商品后直接提交；单文字字段按非空行自动拆成独立订单（最多100笔），多字段及媒体整组构成一笔。文字填写后自动前往下一项，图片和文件可连续追加后点击下一项；全部字段必填，最终统一预览确认。预览尽量复用原消息，取消已有资料的报单需要再次确认。余额不足不创建订单、不冻结积分，资料保留；充值后返回原预览重新核对商品版本和余额，仍需客户确认提交。

管理员 `/admin` 进入私聊后台，常用入口为待处理订单、商品管理和积分管理。异常恢复命令收在「异常处理」中。商品向导逐项填写名称、价格、说明和预计时间，再输入字段名称并点选文字、图片或文件，支持 1 至 10 项。修改时可保留原值，预览确认按钮绑定本次版本。历史订单保存商品快照。客户首页显示可用积分，冻结积分仅在非零时显示；短名称商品两列、长名称单列，每页最多 8 件，翻页更新当前消息。首页保留充值积分入口，不提供订单列表和进度入口，提交后等待管理员直接回单。旧消息中的订单按钮仍校验归属。

管理员待处理批次和批次内订单每页最多 8 项。进入指定子订单，**回复该订单详情消息**添加文字、图片、文件回单；商品、积分和退款向导中的回复优先作为向导输入。查看/删除回单后，点击「发送回单」预览全部内容，再确认发送；确认时在锁定事务内比对回单快照，变动则需要重新预览。每条 Telegram 明确返回消息ID后记录结果，全部交付后扣费。仅冻结余额允许退款；空单要求无回单，原因可选，二次确认后全额解冻。

单文字字段的整批待处理订单支持「批量回单」。管理员逐行填写「账号 结果」，空单填「账号 空」。逐行校验后预览确认，客户收到一条汇总回单，明确送达后事务内扣费、退回空单冻结积分。结果不明确时保留冻结，管理员从异常处理核实恢复。

OKPay 配置使用 `OKPAY_ENABLED=false` 默认关闭。充值卡仅展示金额、积分和中文状态，提供「去付款」「检查到账」及返回入口。首次确认入账由持久事件统一更新原充值卡，移除付款按钮；重复查单不重复入账。卡片与待恢复草稿保存在数据库，重启后仍可恢复。创建结果不明确时保留原单查单入口，再输入相同金额也会打开原单。代付积分归创建订单的客户。请求使用明确标识应用的 User-Agent，付款证据经过签名、商户、订单、金额和币种校验后入账。
