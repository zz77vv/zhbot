## 独立审阅与修正

按代码审查技能启动独立只读审阅代理（用户指定 GPT-6.1 Sol / high）。审阅发现 HTTP 500 配合错误码 400/429 时仍可能误判为明确失败或可重试，影响冻结积分。已先写失败回归，再统一把 HTTP 与 JSON 状态冲突归为未知；现在不得据此释放或自动重发。

另修正重复确认已失败订单时的提示：显示当前订单状态，不再误称积分仍冻结。

首轮审阅当时确认 61 项测试通过，没有发现其他 Critical、Important 或 Minor 问题。审阅明确不判断真实 Telegram/OKPay 兼容性、支付商身份保证、部署就绪或缺失快照兼容性：这些没有实测/原始材料，不能由代码审查替代。对应限制保留在本记录和 README 中。

### 后续审阅：空个人草稿切换目标串单

在提交 `40cf737` 复现：管理员已有空个人客户草稿，并选中另一客户的已预览回执。发送 `/draft` 时，先切换 selection，再因空草稿抛出 RuleError；整个 dispatch savepoint 回滚，selection 留在 receipt。下一条“个人模拟文字”进入客户回执：个人草稿 0 项，客户回执由 1 项变为 2 项。

修复使用独立的事务性 `resume_customer` 明确处理目标切换：空草稿切换成功并提示添加材料；缺失个人草稿时清除旧编辑目标并提示创建；非空草稿仍必须等待完整预览发送确认。业务与 polling 游标仍共同提交，未把目标切换移出更新事务。

新增 4 项回归，其中空草稿、缺失草稿及存储失败后重试 3 项在修复前失败，非空草稿预览门槛对照通过。修复后相关 27 项及全套 65 项通过；测试包含重启后个人文字/图片/文件路由、重复更新去重、客户回执内容/版本/预览资格不变、客户冻结与账本不变、无额外交付批次。父线程的进一步独立审阅仍在进行，本记录不声称后续审阅已结束。

### 后续审阅：管理员撤权后的队列隐私

复现：管理员 `/order` 读取的客户详情排队后，另一个 Service 以管理员集合 `{9002}` 打开数据库并恢复，仍能领取发给旧管理员 9001 的详情。部分回执预览在撤权后也能继续领取附件。

修复为 batches 持久化 audience，所有管理详情/列表/通知标为 admin，回执预览强制为 admin；客户预览、个人信息回复与已确认交付为 customer。领取消息、重启恢复及完成预览时核对当前权限；未获授权的管理批次取消未发送部分并记录审计，不能解锁交付。保留已发/未知历史，不把撤权视作客户交付失败或释放冻结。

兼顾本分支 schema 1 已排队数据：原 note 不包含可信权限元数据，不能靠当前名单或文本猜测，schema 2 升级后以 legacy 标记并保守取消未发送部分；明确的客户预览/交付及回执预览分别映射到对应受众。只有本新应用数据库可升级，未知旧库仍拒绝。

首批 6 项权限测试中，订单详情、部分预览、管理列表及旧队列迁移 4 项修复前失败，正常管理员和已确认客户交付对照通过；另补新单通知与最终预览确认时撤权 2 项。修复后 8 项权限测试、35 项相关测试和全套 73 项通过，离线演示/编译/差异检查通过。进一步独立审阅仍在进行。

### 后续审阅：支付截止、人工处置与身份契约

在 `bb2b737` 新增首批 15 项加固测试，14 项失败、1 项已有同用户申请并发保护对照通过：证实到截止仍会调用创建接口、迟到创建响应变 pending、缺少审计关闭入口，以及不同但可信的订单/交易 ID 被不当拒绝。

现将平台订单与结算交易独立认领和防重，不声称官方字段等价；创建领取/调用前检查截止，响应迟到不发布链接；新增管理员私聊本地关闭、不入账且保留后续查单与审计；观察保留实际付款时间与本地观察时间，迟发现不推断晚付。首次自动入账采用截止前完整可信观察规则，具体业务决策见 PAYMENT_STATE_MACHINE.md。更正旧测试：不同 ID 不等于身份冲突；同一账单后来更换结算交易身份才是冲突。

共新增 24 项测试。支付相关 35 项、全套 97 项通过；包含跨连接同笔交易只能有一个订单入账、同创建任务只调用一次、关闭与查单互斥、恢复后旧响应不自动复活、关闭后迟到交易不得转给新单、schema 2 已入账交易升级后仍防重。离线演示仍为 completed / 可用2 / 冻结0 / 3条账变 / 5项回执；编译和差异检查通过。真实接口、签名、时间字段及身份能力仍未验证，进一步审阅继续。
