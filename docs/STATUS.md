## 2026-11-07 更新

`/start` 首页采用「综合服务」、可用积分和商品按钮，冻结积分仅在非零时显示。商品按钮只显示名称，价格在商品详情展示。标题、余额和充值使用 NewsEmoji 自定义表情，正文实体使用 UTF-16 偏移；明确拒绝后回退普通表情，网络不明时不重试。每页最多 8 件商品，翻页更新当前消息；商品下架后旧页自动回到有效页，空目录保留充值入口。

全面排查后补齐商品卡、提交成功、完成通知和批量回单标题的自定义表情。内置成功图标使用表情包中实际存在的 ✔️，批量标题使用 ✉️；单笔原始回单和批量结果正文保持原样。无关的 400 错误不再永久关闭表情，重复编辑同样内容不再补发首页。错误对象只保留安全分类，不保留接口原始描述。

本轮表情修复的本地完整回归共 86 项，82 项通过，4 项因 Windows 或权限限制跳过，无失败。独立复查覆盖系统图标清单、实体偏移、回单正文和发送/结算边界；服务器测试实例已更新并确认服务运行，最终客户端动画显示仍需在新生成的消息中查看。

客户报单采用商品卡、确认卡和接单回执。根据后续体验调整，客户首页移除「我的订单」，提交、回单和结算通知不再提供订单进度入口；客户等待管理员直接回单。商品短名称两列排列、长名称单列，旧消息中的订单查询仍校验归属。后台首页保留待处理订单、商品和积分管理，异常说明独立入口。商品字段支持输入名称后点选类型，保存和附件删除按钮绑定本次版本。

单文字字段批次支持逐行回单、预览确认、整批汇总发送和原子扣费/空单退分。网络结果不明时保留冻结，通过已留审计的人工核实恢复。按钮采用 NewsEmoji 表情包和 Telegram 支持的颜色样式，拒绝自定义图标时使用普通 Emoji。

测试实例完成一笔 2 USDT 真实付款和入账核对。充值界面只展示本次订单，建单异常保留原单查询入口。HTTP 请求使用明确应用标识，修复默认客户端标识被 Cloudflare 拒绝的问题。付款后的重复查单和归属保护有离线覆盖。

备份和检查命令以只读方式打开已有数据库，拒绝覆盖备份目标，发布前验证完整性。长时间停用后重用的 Telegram 更新 ID 会先归档历史，防止被旧记录误跳过。

## 风险与后续验收

1. OKPay HTTP适配与上传SDK已落地，但当前无真实凭据/联调证据，默认关闭。先在隔离测试机器人配置环境并完成小额支付/查单/代付验收，不可直接正式收费。整理稿引用的官方PDF和A/B/C向量仍未取得。
2. Telegram发送无本项目可用的幂等键；超时/崩溃可能已经送达。保留冻结并人工核实，禁止盲目重发、扣费或退款。
3. 入站处理中断采用隔离，可能需要核对业务后重新输入；不宣称恰好一次交互或所有消息永不丢失。
4. SQLite限单实例，本项目通过文件锁限制；大量订单/长队列需要容量测试和后续存储方案。
5. 资料保存在SQLite（Telegram媒体file_id，非媒体二进制）。保留期限、删除策略、加密备份由运营者在部署前确定，当前未自动删除历史资料。
6. 提供测试Bot Token、唯一管理员ID、隔离网络环境；通过官方安全通道配置商户凭据，安排小额支付/代付及所有失败场景验收；不得提交密钥到GitHub。

## 上传材料后的补齐

真实适配调用payLink、checkDeposit、checkTransferByTxid，验完整响应签名和商户，两次查单确认实付/币种/订单归属。平台单号在创建时持久化，账本与充值通知事务内写入。代付不改变积分归属。创建超时保留原订单，可可信查单恢复；缺链接时只允许管理员核实商户后台后补链接，不伪造链接、不自动重建。历史分页保留旧单可达。详细来源哈希、核验规则及尚待真实验证项目见OKPAY.md。
