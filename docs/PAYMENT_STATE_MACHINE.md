# 离线充值状态机与验收规则

这是本应用的内部开发契约，不是 OKPay 官方字段或能力承诺。真实运行入口固定使用 DisabledGateway，没有真实支付网络实现、签名实现、回调或启用开关。本轮只使用模拟身份、金额和证据验证规则。

## 时间与自动入账

- 本地 `created_at` 固定创建时刻，`expires_at = created_at + 600`，不因排队、接口响应、重启或人工处置延长。
- 创建任务领取时、紧邻接口调用前都检查截止。已到截止则取消创建任务，标记本地 expired，不调用创建接口。不能由本地检查保证上游何时收到请求。
- 请求已发出但响应迟到，或者处理创建响应时已到截止：保留经验证的平台订单身份并转 review，清除 pay_url，不发布可付款链接。不能据此认定上游没创建订单，也不更换原单号自动重试。
- `observed_at` 是适配器返回证据时由 worker 捕获的本地时间。`paid_at` 仅表示适配器有依据认证的实际付款时间；无法认证时必须为 None。发现时间、创建时间和回调到达时间不得代替付款时间。
- 自动入账需完整来源、商户、订单、本人、金额、USDT、已付状态与交易身份核实，且 `created_at <= paid_at <= observed_at < expires_at`。数据库处理时钟还须不早于 observed_at，本地状态须仍为 pending。
- 若完整可信证据已在截止前取得，但仅数据库提交延后，允许在状态仍 pending 时提交；不把数据库处理延迟说成晚发现。若本地状态已经变成 expired/unknown/review，则仍人工核实。
- 截止后首次发现已付，即使模拟证据给出窗口内付款时间，也保守转 review，不自动加分。原因记录“发现较晚、需核实”，不据此断言实际晚付。实际付款时间缺失、在窗口外、晚于观察时间或时钟顺序异常也都转 review。

后两条是本轮采用的保守业务决策，不是平台保证；真实接入前应由用户确认自动入账/人工核实边界，并先取得原始时间字段及其认证语义。

## 两类身份分别防重

`Evidence.platform_id` 是适配器认证的平台订单身份，`Evidence.transaction_id` 是适配器认证的结算交易身份。它们可以相同或不同，应用不假设等价。模拟器刻意使用不同值，不能因此推断真实 OKPay 的字段关系或字段可用性。

未来适配器必须用官方契约证明这些身份如何与本地单号关联；不能凭截图、用户填写或任意拼接构造结算身份。当前没有这样的真实适配器。

`payment_identity_claims` 分别对平台订单和结算交易加唯一约束，同一单每类也只能认领一个值。经认证且绑定本地单号的已付证据即使需要人工核实，也先保留身份认领，避免已关闭/迟到单的同笔钱被其他订单自动使用。来源或关联不可信时不认领。入账还须通过 `payment_transactions` 的交易唯一约束，支付终态、积分账变和入账交易同事务提交。

## 状态与人工关闭

| 本地状态 | 含义 | 是否阻止该用户重新申请 |
| --- | --- | --- |
| queued | 已保存，尚未领取创建任务 | 是；截止后可安全取消未发起任务 |
| creating | 本地任务正在执行；不代表上游已创建 | 是；进程中断则 unknown |
| pending | 及时创建并保存，尚未确认付款 | 窗口内是；窗口结束标 expired |
| expired | 本地窗口已结束，不说明真实付款或上游取消 | 否；后续付款证据仍核实 |
| unknown / review | 请求结果不明、身份/金额/时间等未通过核实 | 是，直到管理员处置 |
| closed | 管理员附依据关闭本地核实单，没有加分/退款 | 否；保留原单、身份认领、历史和后续查单 |
| closed_review | 关闭后出现新证据，需再次人工核实 | 是，可再次附依据关闭；不能自动入账 |
| paid | 已通过完整规则原子入账 | 否；重复事件不能再次入账或用关闭操作撤销 |

管理员私聊命令：`/payment_close 充值单号 核实依据`。仅允许 unknown、review、expired、closed_review；拒绝空依据、非管理员、已入账单、仍在执行的任务。尚未开始的查单任务可在关闭时取消。重复关闭幂等，并保留最初关闭审计；有新证据转 closed_review 后再次处置会新增审计。

**关闭不等于平台取消，不代表未收款，不退款，不删除交易认领，也不提供强制加分。** 允许重新申请是解除本地流程阻塞，不是丢弃旧款责任。已经发出的平台链接可能仍有效，需要人工对账；如存在真实款项，后续补记或退款必须另行设计、审查和授权，当前未实现。

## 恢复、重复与并发

- 每次观察按 job_id 唯一落 `payment_observations`，存本地观察时间和有界的内部事实，排除支付链接和原始令牌/响应；同时保留各次人工处置审计。重复处理同一任务不重复落证据或入账，新查单可保留新的观察。
- 恢复将执行中任务置 unknown 并记审计；创建结果不明不再创建。已恢复/关闭的旧任务迟到响应只能留证和人工核实，不得覆盖为 pending/paid。
- SQLite BEGIN IMMEDIATE、活动任务唯一索引和身份唯一约束，分别串行化同用户创建、任务领取、人工关闭与证据入账。处置与执行中的查单冲突时拒绝关闭；完成或恢复后可再次核实。
- schema 3 事务性添加观察与身份表，支持本新应用 schema 1/2 升级。schema 2 已入账交易仍通过原交易表防止重用，旧版未保存过的证据无法重建。未知旧快照数据库仍拒绝；这不是旧快照的数据迁移工具。

测试与真实支付证明是不同的事。`verified=True` 只是受信模拟适配器的内部断言；没有完成官方文档、SDK、身份与时间能力验证前，不能把它暴露为用户可提交的证明或用于真实收款。
