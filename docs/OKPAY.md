## 实际接口及验证

固定根地址 `https://api.okaypay.me/shop`，POST `application/x-www-form-urlencoded`：

1. `payLink`：发送整数USDT的金额字符串、coin=USDT、本地唯一ID作为unique_id。SDK为每次请求生成id/timestamp/nonce/sign。完整成功响应验签、商户ID核对后保存order_id和pay_url；创建链接本身不增加积分。
2. `checkDeposit`：按unique_id查单。完整成功响应验签，核对商户、本地商户单号、已绑定平台单号、金额。待付状态不入账。
3. `checkTransferByTxid`：checkDeposit实付后按返回/已绑定平台单号查询，再次验签，确认双方订单号、amount、coin=USDT、status=1；存在type时必须为deposit。缺字段、签名错误、两次查单状态冲突均拒绝入账。

所有HTTP请求保留系统代理与TLS验证，禁止跟随重定向；设置超时和响应大小上限，拒绝重复JSON键、歧义点号字段和不支持的签名数据类型。JSON数字保持原始字符串，避免金额被浮点重新格式化。未签名warning/error只能视为失败，不能确认收款。错误信息不回显原始响应、签名参数或商户密钥。

代付允许，pay_user_id不与创建订单客户ID强行比较，也不用于改变客户归属。积分仅记入数据库创建充值单时保存的user_id。同一充值和同一平台交易号通过事务、唯一约束和钱包流水唯一键防止重复入账。

`payment_checks` 保存创建/检查结果、平台单号、验证响应SHA256摘要和核验时间；不保存原始付款人资料或密钥。入账、流水与充值通知事件在同一事务中持久化。摘要可支持本地追踪，不能替代商户账单或完整支付证据。

本版只实现收款、手动查单，不开放提现/转账，也未启用自动回调入账。未设置自动过期或猜测付款时效。

## 配置

`.env.example` 给出空凭据，`OKPAY_ENABLED=false` 默认关闭。

测试环境准备好后，运营者通过安全环境变量注入 `OKPAY_MERCHANT_ID`、`OKPAY_MERCHANT_TOKEN`，显式设置 `OKPAY_ENABLED=true`。这个配置会让运行中的机器人提供真实付款链接，必须先在隔离测试机器人使用；不能因此视为生产启用已获授权。`check`命令只检查本地配置/数据库，不请求OKPay、不宣称网络验证成功。

充值菜单直接提示输入金额。创建成功后，该笔订单显示「支付订单」和「检查支付状态」两个按钮。创建结果不明确时，该笔订单仍可查单。已入账订单只保留查单按钮。

## 异常恢复

创建前先保存原unique_id；超时或不确定响应保留原单，不更换单号盲目重试。相同客户/金额/商户的未决单：有可用付款链接则复用；创建结果不确定则提示检查原订单。进程在请求中断时保留的created状态也可通过原单查单恢复。

可信查单返回平台ID时，绑定原订单；实付且所有验证通过后可正常入账。若查明待付但缺少pay_url，材料没有取回支付链接的接口：**不会拼造Telegram链接或重复调用payLink**。客户联系管理员，管理员从商户后台核实并取回对应原单链接后，可使用：

```
/paymentlink 本地充值ID 平台订单ID HTTPS原单支付链接 核实原因
```

仅唯一管理员可操作，必须先通过可信查单绑定同商户/同平台订单，且订单待付、原链接缺失；已有链接或已入账不能覆盖。操作记审计，只补链接、不改付款状态、不加积分。恢复后客户在充值菜单输入原金额，即可重新打开原单。

若原单始终无法恢复，管理员先按本地充值 ID（商户单号）向 OKPay 核实，取得明确结论后可执行：

```
/paymentclose 本地充值ID absent|closed 核实凭据
```

- `absent` 用于 OKPay 明确确认原单从未创建，且本地也未记录平台单号或付款链接。
- `closed` 用于 OKPay 明确确认原单未付款、已永久关闭且原链接无法继续付款。

超时、一般查单错误、暂时查不到或仅显示待付款时，保持原单未决。关闭只改变本地状态并记审计，允许客户重建同金额的单。已关闭的原单仍可查单；未支付结果不会重新打开，若此后获得通过原有校验的实付证据，仍按原单归属入账一次。
